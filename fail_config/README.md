# Практическая работа 6 вариант 1

Проект находится в папке `fail_config`, файл проекта — `SupportTicketsApi.csproj`

Это API тикет-системы поддержки на C# с регистрацией, входом по JWT и вложениями к заявкам

Пользователь видит свои заявки и может прикреплять к ним файлы, а агент видит заявки, которые назначены ему

## Что нужно для запуска

- .NET SDK 8 или новее и доступ к NuGet для первого восстановления пакетов
- Visual Studio с поддержкой ASP.NET Core либо терминал PowerShell
- Проект рассчитан на .NET 8, настройка RollForward позволяет использовать установленную среду .NET 10

Для проекта нужны .NET и NuGet, npm и Node.js не требуются

## Первый запуск из PowerShell

Открой терминал в папке `fail_config`

```powershell
.\setup-secrets.ps1 -WithAgent
.\run.ps1
```

`run.ps1` сам выбирает 64-разрядный dotnet, восстанавливает пакеты при необходимости и запускает профиль `http`

Скрипт создаёт случайный ключ JWT в User Secrets, затем просит придумать пароль агента длиной не меньше 8 символов

Пароль вводится скрыто, имя агента по умолчанию — `agent`

Этот пароль используется только при создании нового агента, повторный запуск скрипта не меняет пароль уже существующей учётной записи

Если агент пока не нужен, выполни `.\setup-secrets.ps1` без `-WithAgent`

При сообщении PowerShell о запрете запуска скриптов можно разрешить только этот запуск

```powershell
powershell -ExecutionPolicy Bypass -File .\setup-secrets.ps1 -WithAgent
powershell -ExecutionPolicy Bypass -File .\run.ps1
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

Swagger открывается по адресу `http://localhost:5086/swagger`

База SQLite создаётся автоматически при запуске, а папка `storage` появляется после успешной загрузки первого файла

Если команда `dotnet` не видит SDK, хотя он установлен, используй 64-разрядный исполняемый файл

```powershell
& "$env:ProgramFiles\dotnet\dotnet.exe" --info
& "$env:ProgramFiles\dotnet\dotnet.exe" run --launch-profile http
```

## Запуск из Visual Studio

1. Открой `SupportTicketsApi.csproj`
2. Восстанови NuGet-пакеты через сборку проекта
3. Один раз выполни `setup-secrets.ps1 -WithAgent` в терминале этой папки
4. У зелёной кнопки запуска выбери профиль `http` и нажми F5
5. Перейди в браузере на `http://localhost:5086/swagger`

## Как показать работу в Swagger

1. Открой `POST /api/auth/register` и создай пользователя, передав `userName` и `password`
2. Создай второго пользователя с другим именем, он пригодится для проверки чужого доступа
3. Войди первым пользователем через `POST /api/auth/login` и скопируй значение `token`
4. Нажми Authorize и вставь само значение токена, Swagger добавляет слово Bearer
5. Создай заявку через `POST /api/tickets`, передав `title` и `text`, и запомни её `id`
6. В `POST /api/tickets/{ticketId}/files` укажи этот ID, нажми Try it out и выбери файл в поле `file`
7. Разрешены `.jpg`, `.jpeg`, `.png` и `.pdf`, успешная загрузка возвращает 201 и ID файла
8. Посмотри список через `GET /api/tickets/{ticketId}/files` и скачай файл через `GET /api/files/{id}`

В списке файлов есть исходное имя, тип, размер и дата, физического пути в ответе нет

Для проверки агента сначала получи его ID из `GET /api/tickets/agents`, затем автором заявки вызови `PUT /api/tickets/{id}/agent` с телом `{"agentId": 1}`, подставив настоящий ID

Войди именем `agent` и паролем, который ввёл в скрипте настройки, после чего замени токен в Authorize

Агент сможет посмотреть назначенную ему заявку и скачать её вложения, а загружать новые файлы может автор заявки

## Какие проверки показать на защите

| Действие | Ожидаемый результат |
|---|---|
| `GET /api/config` без входа | Среда, лимит, расширения и длина ключа без самого ключа |
| Загрузить настоящий разрешённый файл к своей заявке | 201 и файл с именем Guid в `storage/uploads/год/месяц/день` |
| Переименовать PNG в jpg и загрузить | 400 из-за несовпадения первых байтов с расширением |
| Загрузить пустой файл или файл больше лимита | 400 с объяснением |
| Скачать свой файл | 200 и исходное имя файла |
| Скачать файл второго пользователя | 403 |
| Скачать файл без токена | 401 |
| Скачать файл назначенным агентом | 200 |
| Открыть несуществующий файл | 404 |

Примеры запросов также находятся в `requests.http`, в нём оставлены заглушки для паролей, токенов и ID

Локально проверены сборка без предупреждений и ошибок, загрузка, права автора и агента, ответы 201, 400, 401, 403 и 404, проверка MIME и файл ровно в лимит

Также проверено скачивание части файла через Range с ответом 206

## Настройки и секреты

В `appsettings.json` лимит равен 1048576 байт, то есть 1 МиБ, а `Jwt:Secret` оставлен пустым

Настройки читаются через классы `FileUploadOptions` и `JwtOptions`, проверка выполняется при старте

Рабочий ключ лежит в User Secrets вне проекта, команда для повторного создания ключа — `.\setup-secrets.ps1`

Повторный запуск скрипта создаёт новый ключ JWT, поэтому старые токены перестают подходить и нужно войти заново

Не копируй рабочий ключ в `appsettings.json`, `launchSettings.json`, README или Git

Для проверки отказа при коротком ключе останови API и выполни

```powershell
Remove-Item Env:Jwt__Secret -ErrorAction SilentlyContinue
& "$env:ProgramFiles\dotnet\dotnet.exe" user-secrets set "Jwt:Secret" "short" --project .
.\run.ps1
```

Приложение должно остановиться до открытия Swagger с сообщением о настройках JWT

Отсутствие ключа можно проверить командой `& "$env:ProgramFiles\dotnet\dotnet.exe" user-secrets remove "Jwt:Secret" --project .` и повторным запуском

После проверки восстанови ключ скриптом `setup-secrets.ps1` и запусти проект снова

Затем повтори вход через `POST /api/auth/login`, чтобы получить токен с новой подписью

## Режим Production

Файл `appsettings.Production.json` меняет только лимит на 204800 байт, то есть 200 КиБ

В Production User Secrets не подключаются, ключ нужно передать переменной окружения `Jwt__Secret`

Следующие команды спрашивают ключ скрыто, задают его в текущем терминале и передают запущенному API

```powershell
$key = Read-Host "Введите JWT-ключ не короче 32 символов" -AsSecureString
$env:Jwt__Secret = [System.Net.NetworkCredential]::new("", $key).Password
.\run.ps1 -Profile Production
```

После остановки API убери переменную из текущего терминала

```powershell
Remove-Item Env:Jwt__Secret
```

В `GET /api/config` должны быть среда Production и лимит 204800, остальные настройки берутся из базового файла

Без внешнего ключа Production также не должен запускаться

## Где находится код

| Папка или файл | Для чего нужен |
|---|---|
| `Controllers` | Принимает запросы и возвращает HTTP-ответы |
| `Contracts` | Описывает входные данные и ответы API |
| `Models` | Описывает пользователя, заявку и метаданные файла |
| `Services` | Выполняет вход, проверяет права и сохраняет файлы |
| `Data` и `Migrations` | Настраивают SQLite и структуру таблиц |
| `Options` | Хранят настройки загрузки и JWT в обычных C#-классах |
| `Program.cs` | Подключает сервисы, JWT, Swagger и контроллеры |
| `setup-secrets.ps1` | Создаёт локальные секреты без записи в исходники |
| `run.ps1` | Выбирает 64-разрядный dotnet и запускает нужный профиль |

## Подготовка к сдаче

По заданию нужен рабочий проект и приватный репозиторий GitHub, отдельный отчёт не нужен

Создай приватный репозиторий и отправь туда исходники самостоятельно из Visual Studio или привычным способом

Перед публикацией проверь `git status` и дерево файлов на GitHub

`.gitignore` исключает результаты сборки, базы SQLite и папку `storage`, а User Secrets изначально лежат вне проекта

В репозитории должны остаться пустой `Jwt:Secret` и настройки лимитов, но не реальные ключи, пароли и скопированные JWT
