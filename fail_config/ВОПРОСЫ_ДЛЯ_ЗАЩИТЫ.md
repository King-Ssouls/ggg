# Вопросы для защиты практической работы 6

## Что делает проект

Проект хранит заявки пользователей и позволяет прикреплять к ним изображения и документы, файлы доступны автору заявки и назначенному агенту

## Почему работа находится в новой папке

Папка `fail_config` содержит самостоятельный проект варианта 1, в нём добавлена основа с пользователями и JWT, которая нужна для файловой части задания

## Какие главные классы есть в проекте

`AppUser` хранит учётную запись, `Ticket` описывает заявку, а `StoredFile` хранит метаданные файла и ссылку на заявку

Контроллер принимает запрос, `AuthService` выполняет регистрацию и вход, `FileService` проверяет и сохраняет файлы, а `AppDbContext` работает с SQLite

## Какие функции выполняют главную работу

| Функция | Что делает |
|---|---|
| `RegisterAsync` | Проверяет имя и сохраняет пользователя с хешем пароля |
| `LoginAsync` | Проверяет пароль и создаёт подписанный JWT |
| `UploadAsync` | Проверяет файл, права автора и сохраняет загрузку |
| `GetListAsync` | Возвращает доступные метаданные файлов заявки |
| `DownloadAsync` | Проверяет доступ и открывает поток файла |
| `CheckFileAsync` | Сверяет размер, расширение и сигнатуру |
| `CheckReadAccess` | Разрешает чтение автору и назначенному агенту |
| `GetUserId` | Получает ID вошедшего пользователя из claims |
| `EnsureAgentAsync` | Создаёт агента из локальных настроек, если он ещё не создан |

## Что такое DTO

Это класс данных для запроса или ответа, с его помощью клиент передаёт только нужные поля и не получает служебные поля базы

## Как создаётся заявка

Пользователь входит, получает JWT и отправляет `title` и `text`, сервер берёт ID автора из токена и сохраняет заявку в базе

## Зачем нужны роли User и Agent

Обычный пользователь работает со своими заявками, агент читает заявки, которые назначены ему, выбрать роль Agent при обычной регистрации нельзя

## Кто может загрузить и скачать файл

Загрузить может автор заявки, скачать может автор или назначенный агент, другой пользователь получает 403

## Что такое JWT

Это подписанный токен для передачи сведений о вошедшем пользователе, в нём есть ID, имя, роль и время окончания действия

Сервер проверяет подпись, издателя, получателя и срок действия токена перед выполнением защищённого запроса

## JWT зашифрован

Обычный JWT можно прочитать, подпись защищает от незаметного изменения данных, поэтому пароли и секретный ключ в токен не кладут

## Что такое claims

Это поля внутри токена, из них API получает ID пользователя и его роль, владелец файла не передаётся через форму загрузки

## Где находится секрет JWT

В Development он лежит в User Secrets вне папки проекта, а в Production приходит из переменной окружения `Jwt__Secret`

В `appsettings.json` значение секрета пустое

## Что меняет повторный запуск setup secrets

Он создаёт новый ключ JWT, поэтому ранее выданные токены становятся недействительными и пользователям нужно войти заново

Пароль SeedAgent используется только при создании нового агента, изменение этого секрета не сбрасывает пароль уже существующей записи

## Как хранятся пароли пользователей

В базе хранится хеш пароля, `PasswordHasher` создаёт его при регистрации и проверяет при входе, сам пароль в базе не сохраняется

## Почему User Secrets не попадают в Git

Их файл находится в профиле Windows за пределами проекта, в проекте хранится только `UserSecretsId`, по которому приложение находит нужное хранилище

User Secrets предназначены для локальной разработки и сами по себе не являются зашифрованным хранилищем

## Что произойдёт с коротким ключом

Проверка `ValidateOnStart` остановит приложение, если секрет короче 32 символов или не заполнены обязательные настройки JWT

## Зачем нужны FileUploadOptions и JwtOptions

Они представляют настройки обычными C#-свойствами, сервис получает объект через `IOptions` и не повторяет строковые ключи конфигурации в разных местах

## Что означает IOptions и Value

`IOptions<T>` передаёт настройки через контейнер зависимостей, а `Value` возвращает сам объект с лимитом, расширениями или настройками JWT

## Какой источник настроек имеет приоритет

Сначала читается `appsettings.json`, затем файл текущей среды, в Development поверх него подключаются User Secrets, а переменные окружения и аргументы запуска могут переопределить предыдущие значения

## Чем отличаются Development и Production

В Development лимит файла 1048576 байт и читаются User Secrets, в Production лимит 204800 байт и секрет ожидается из внешней переменной окружения

Код загрузки при смене среды остаётся тем же

## Что показывает GET api config

Он показывает имя среды, лимит, список расширений и длину секрета, самого ключа, паролей и строки подключения в ответе нет

## Как файл приходит в API

Клиент отправляет `multipart/form-data`, ASP.NET Core представляет часть с именем `file` как `IFormFile`, через него доступны размер, имя и поток содержимого

## Почему загрузка не принимает JSON

Файл передаётся как часть формы, поэтому используется `multipart/form-data`, а JSON подходит для обычных данных вроде названия и текста заявки

## Как проверяется файл

Сначала проверяются наличие содержимого и размер, затем расширение и первые байты, после этого проверяются заявка и право пользователя на неё

Разрешены только jpg, jpeg, png и pdf

## Зачем проверять первые байты

Имя и Content-Type задаёт клиент, поэтому их можно подменить, сигнатура помогает заметить ситуацию, когда файл png переименовали в jpg

JPEG начинается с FF D8 FF, PNG с 89 50 4E 47, PDF с 25 50 44 46

## Полностью ли сигнатура доказывает безопасность файла

Нет, это учебная проверка формата по первым байтам, в большом сервисе могут понадобиться полноценный разбор файла и антивирусная проверка

## Откуда берётся MIME в базе

Сервер сам выбирает `image/jpeg`, `image/png` или `application/pdf` после проверки расширения и сигнатуры

## Почему файл на диске называется Guid

Новое имя не зависит от имени клиента и почти исключает совпадение с другим файлом, исходное имя хранится в базе и используется при скачивании

## Что такое Path Traversal

Это попытка выйти из папки через имя вроде `../../secret.txt`, проект берёт только имя для отображения и создаёт путь хранения из даты, Guid и проверенного расширения

## Почему файлы лежат вне wwwroot

Файлы в wwwroot можно было бы отдавать напрямую, а здесь скачивание проходит через API с проверкой JWT и права на заявку

## Зачем нужны подпапки по дате

Они не дают складывать все загрузки в один каталог и помогают найти файлы по времени загрузки

## Что хранится в таблице файлов

ID, ссылка на заявку, исходное имя, относительный путь, MIME, размер, ID загрузившего пользователя и дата загрузки

Само содержимое файла лежит на диске, а путь не показывается в ответах списка

## Что будет при ошибке сохранения в базу

Сервис обрабатывает ошибку и убирает только что записанный файл, чтобы на диске не оставалась загрузка без записи в базе

## Как скачивание экономит память

API открывает `FileStream` и передаёт его в HTTP-ответ, файл читается частями и целиком в массив байтов не загружается

## Зачем нужен Range и ответ 206

Заголовок Range позволяет запросить часть файла, например для докачки, в ответе 206 сервер передаёт только выбранный диапазон байтов

## Зачем нужны async и await

Они позволяют ждать чтение базы и запись файла без блокировки рабочего потока на всё время ожидания

## Чем отличаются 400, 401, 403 и 404

400 означает, что данные или файл не прошли проверку, 401 означает отсутствие подходящего токена, 403 означает отсутствие права при действующем токене, 404 означает отсутствие заявки или файла

## Зачем серверный лимит немного больше лимита файла

В multipart-запросе кроме файла есть границы и служебные заголовки, запас около 256 КиБ позволяет файлу ровно в лимит пройти в проверку сервиса

## Какие переменные важно понимать

| Имя | Простой смысл |
|---|---|
| `builder` | Настраивает сервисы и параметры приложения |
| `app` | Готовое приложение с подключёнными обработчиками запросов |
| `db` | Контекст для чтения и записи SQLite |
| `user` | Текущий пользователь или его запись в базе |
| `ticket` | Найденная или создаваемая заявка |
| `ticketId` | ID заявки, к которой относится запрос |
| `file` | Файл, полученный от клиента |
| `fileId` или `id` | ID нужной записи файла или заявки |
| `options` | Объект настроек, полученный через IOptions |
| `token` в ответе входа | JWT для входа в защищённые методы |
| `extension` | Проверенное расширение файла |
| `path` | Составленный сервером путь к файлу |
| `stream` | Поток для чтения или записи байтов |
| `cancellationToken` | Сигнал отмены операции, например при отключении клиента |

## Почему нельзя коммитить ключ даже в приватный репозиторий

Git сохраняет историю и копии коммитов, поэтому раскрытый ключ нужно заменить, приватность репозитория не делает сохранённый секрет безопасным

## Что нужно показать преподавателю

Открытый config, успешную загрузку 201, несовпадение расширения и сигнатуры 400, скачивание своим токеном 200, чужим токеном 403 и без токена 401

Также показать Guid-имя на диске, меньший Production-лимит и приватный GitHub без базы, storage и секретов
