# Инструкция по запуску

Эта инструкция поможет открыть проект, задать секрет JWT и проверить работу API через Swagger.

## Что установить

- .NET 8 SDK.
- Visual Studio 2022 с компонентом **ASP.NET и веб-разработка** или терминал PowerShell.

При первом запуске NuGet автоматически загрузит библиотеки проекта. Нужен доступ к NuGet.

## Настройка секрета JWT

Секрет нужен серверу для подписи JWT. В исходном коде и `appsettings.json` его нет.

### Вариант Visual Studio

1. Откройте файл `JwtSupportTickets.csproj` в Visual Studio.
2. Нажмите правой кнопкой по проекту и выберите **Управление секретами пользователя**.
3. В открывшийся файл добавьте JSON. Замените пример на свою случайную строку длиной не менее 32 символов:

   ```json
   {
     "Jwt": {
       "Secret": "замените_этот_пример_своим_длинным_случайным_секретом_123456"
     }
   }
   ```

4. Сохраните файл и закройте его.

### Вариант PowerShell

1. Откройте PowerShell в папке проекта `JwtSupportTickets`.
2. Выполните команду и замените пример на свою случайную строку длиной не менее 32 символов:

   ```powershell
   dotnet user-secrets set "Jwt:Secret" "замените_этот_пример_своим_длинным_случайным_секретом_123456"
   ```

User Secrets хранит настройку отдельно от исходного кода проекта.

## Запуск приложения

### Через Visual Studio

1. Откройте `JwtSupportTickets.csproj`.
2. Дождитесь восстановления NuGet-пакетов.
3. Нажмите **F5** или **Ctrl+F5**.
4. Откройте Swagger по адресу `http://localhost:5168/swagger`. Если приложение вывело другой адрес, откройте адрес из окна запуска и добавьте `/swagger`.

### Через PowerShell

Откройте терминал в папке `JwtSupportTickets` и выполните:

```powershell
dotnet run
```

Затем откройте `http://localhost:5168/swagger` или адрес, который показал терминал.

При первом запуске создаётся SQLite файл `tickets.db` с таблицами пользователей, заявок и refresh-токенов. В этом учебном проекте таблицы создаются автоматически методом `EnsureCreatedAsync`; команды миграций запускать не нужно.

## Проверка регистрации и заявки

1. В Swagger откройте `POST /api/auth/register`, нажмите **Try it out** и отправьте:

   ```json
   {
     "email": "user1@example.com",
     "password": "StrongPass123"
   }
   ```

   Пароль должен быть не короче 8 символов. В ответе придут `accessToken` и `refreshToken`. Новому аккаунту всегда назначается роль `User`.

2. Нажмите **Authorize** в верхней части Swagger и вставьте значение `accessToken` без слова `Bearer`. Нажмите **Authorize**, затем закройте окно.
3. Откройте `POST /api/tickets` и отправьте:

   ```json
   {
     "subject": "Не открывается личный кабинет",
     "text": "После входа появляется пустая страница."
   }
   ```

4. Откройте `GET /api/tickets/my`. В ответе должны быть заявки текущего пользователя.
5. Нажмите **Authorize** → **Logout** и вызовите `GET /api/tickets/my` без токена. Ответ `401` означает, что защищённый метод не пускает неавторизованного пользователя.

## Проверка доступа к чужой заявке

1. Зарегистрируйте второго пользователя с другим email.
2. Войдите вторым пользователем через `POST /api/auth/login` и замените токен в **Authorize** на новый.
3. Попробуйте открыть заявку первого пользователя через `GET /api/tickets/my/{id}`.

Сервер должен вернуть `403`: второй пользователь вошёл успешно, но заявка ему не принадлежит.

## Проверка ролей Agent и Admin

Регистрация не даёт выбрать роль. Это не позволяет обычному пользователю назначить себя агентом или администратором через API. Для учебной демонстрации роли тестовых аккаунтов меняются вручную в SQLite.

1. Зарегистрируйте аккаунты `agent@example.com` и `admin@example.com`.
2. Остановите приложение.
3. Откройте `tickets.db` в SQLite-редакторе, например DB Browser for SQLite. Найдите таблицу `Users` и выполните запросы, заменив email на свои:

   ```sql
   UPDATE Users SET Role = 'Agent' WHERE Email = 'agent@example.com';
   UPDATE Users SET Role = 'Admin' WHERE Email = 'admin@example.com';
   ```

4. Сохраните изменения, перезапустите приложение и заново войдите тестовыми аккаунтами. Новый вход нужен, чтобы получить JWT с обновлённой ролью.
5. Для проверки агента вызовите `GET /api/tickets/unassigned`, затем `POST /api/tickets/{id}/assign`. Агент может закрыть только заявку, назначенную на него: `POST /api/tickets/{id}/close`.
6. Для проверки администратора вызовите `GET /api/tickets/all`. Администратор может закрыть любую заявку через `POST /api/tickets/{id}/close`.

Если таблица не появилась, сначала запустите приложение и зарегистрируйте хотя бы одного пользователя, а затем остановите его перед ручным изменением базы.

## Проверка refresh-токена

1. Скопируйте `refreshToken` из ответа `POST /api/auth/login`.
2. Вызовите `POST /api/auth/refresh` и отправьте:

   ```json
   {
     "refreshToken": "вставьте_сюда_значение_refreshToken"
   }
   ```

3. Сервер вернёт новую пару токенов. Старый refresh-токен повторно использовать нельзя. Повторная отправка отозванного токена возвращает `401` и отзывает действующие refresh-токены этого пользователя.

## Частые проблемы

- **Приложение сообщает, что не задан `Jwt:Secret`.** Добавьте секрет через один из способов выше. Его длина должна быть не менее 32 символов.
- **Swagger не открывается.** Проверьте адрес, который показал Visual Studio или `dotnet run`, и добавьте `/swagger`.
- **Порт занят.** Закройте другое приложение на порту или измените `applicationUrl` в `Properties/launchSettings.json`.
- **Нет доступа к NuGet.** Дайте Visual Studio или `dotnet run` восстановить пакеты при подключении к сети.

Локально проект использует HTTP для простоты учебного запуска. При реальном размещении API необходимо использовать HTTPS, чтобы защищать пароль и токены при передаче.
