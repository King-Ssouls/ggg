# Установка и запуск ConcertTicketsApi

## Требования

- .NET 8 SDK. Выберите SDK в Visual Studio Installer или установите .NET 8 SDK с сайта .NET.
- Доступ к NuGet при первом восстановлении пакетов.
- SQLite ставить отдельно не нужно: база будет файлом `concerts.db`.

## Через Visual Studio

1. Откройте `ConcertTicketsApi.csproj`.
2. Дождитесь восстановления NuGet. Если автоматическое восстановление отключено, выполните **Сборка → Восстановить пакеты NuGet**.
3. Выберите профиль `ConcertTicketsApi` и запустите проект. Swagger откроется на `https://localhost:7261/swagger`.

## Через PowerShell

Откройте терминал в папке `ConcertTicketsApi`:

```powershell
dotnet --version
dotnet restore
dotnet tool restore
dotnet ef migrations list
dotnet ef database update
dotnet run
```

Команда `dotnet tool restore` устанавливает локальный `dotnet-ef` версии 8.0.31 из `.config/dotnet-tools.json`. У второго проекта своя версия инструмента, поэтому они не конфликтуют. В проекте EF Core 8.0.31 для обоих пакетов — SQLite и Design. При запуске приложение само применяет миграции, поэтому `dotnet ef database update` нужен для ручного выполнения и демонстрации команд.

Если сертификат HTTPS ещё не доверен, выполните `dotnet dev-certs https --trust` и перезапустите приложение. Удаление `concerts.db` сбрасывает базу; при следующем старте миграции и демонстрационные записи создадутся снова.

## Проверка демонстрационных сценариев

Откройте `requests.http` в Visual Studio/VS Code с REST Client либо используйте Swagger. На пустой базе автоматически создаются 45 событий. Для продажи используйте сектор `1`, категорию цены `1`, покупателя `3`.

Для конфликта вместимости сначала прочитайте сектор и запомните `Version`, затем через `PUT /api/sectors/1` уменьшите вместимость до числа уже проданных мест плюс одно, выполнив одну продажу. Повторная продажа должна вернуть 409. Чтобы показать конфликт версии, повторите PUT, передав старый `Version`.

Для отчёта сравните консольный SQL после `/api/events/n-plus-one` и `/api/events/with-sectors`. Проверьте отсутствие `internalBarcode` в ответах списка и деталей билета. Продажа и возврат логируются SQL EF Core; `InternalBarcode` не включается в ответы и не включён в логирование значений параметров.
