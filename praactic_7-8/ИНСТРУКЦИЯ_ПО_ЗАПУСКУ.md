# Инструкция по запуску

## Что установить

- .NET 8 SDK.
- Visual Studio 2022 с компонентом **ASP.NET и веб-разработка** или PowerShell.
- Для дополнительного задания Prometheus/Grafana — Docker Desktop с Compose.

При первом запуске .NET автоматически загрузит NuGet-пакеты. Для внешнего API и карт нужен доступ к интернету.

## Запуск приложения

### В Visual Studio

1. Откройте решение `IssTracker.sln` из папки `praactic_7-8`.
2. Дождитесь восстановления NuGet-пакетов.
3. Нажмите **F5** или **Ctrl+F5**.
4. Откройте Swagger вручную по адресу `http://localhost:5168/swagger`.

### В PowerShell

Откройте PowerShell в папке `praactic_7-8` и запустите:

```powershell
dotnet run --project IssTracker.Api/IssTracker.Api.csproj
```

Если приложение показало другой порт, используйте его вместо `5168` во всех адресах ниже и в файле `prometheus/prometheus.yml`. Приложение слушает сетевые интерфейсы компьютера, чтобы контейнер Prometheus мог подключиться через `host.docker.internal`.

При старте приложение применит миграцию и создаст файл базы `IssTracker.Api/iss-tracker.db`. Фоновый сервис сразу сделает первую попытку, а затем будет обновлять данные раз в 30 секунд.

## Проверка основной части через Swagger

1. Вызовите `GET /api/iss/latest`. После первого успешного запроса здесь будут координаты МКС и поле `isStale`.
2. Через несколько интервалов вызовите `GET /api/iss/history?limit=10`. История должна содержать несколько измерений.
3. Вызовите `GET /api/iss/status`. Ответ показывает время последней попытки, последнего успеха, последнюю ошибку и число ошибок подряд.
4. Вызовите `POST /api/iss/refresh`, чтобы запустить обновление вручную. Если фоновой запуск уже идёт, API вернёт `409`; подождите немного и повторите.
5. Откройте `GET /health/live` и `GET /health/ready`. Первый показывает, что процесс жив. Второй показывает, есть ли свежее измерение.
6. Откройте `GET /metrics`. Найдите `iss_sync_attempts_total`, `iss_sync_failures_total` и `iss_sync_duration_seconds`.

Если внешний сервис временно недоступен, последнее успешно сохранённое измерение остаётся в базе. `latest` продолжит его показывать и выставит `isStale`, когда данные станут старше заданного срока.

## Проверка режимов ошибок Polly

Отладочные адреса доступны только при `ASPNETCORE_ENVIRONMENT=Development`. В профиле Visual Studio уже установлено это значение.

Можно вызывать адреса через Swagger или PowerShell. Например:

```powershell
Invoke-RestMethod -Method Post -Uri http://localhost:5168/api/debug/failure-mode/FailTwice
Invoke-RestMethod -Method Post -Uri http://localhost:5168/api/iss/refresh
```

- `FailTwice` — первые два запроса симулятора получают `503`, Polly повторяет запрос и затем получает настоящее измерение.
- `Slow` — симулятор ждёт дольше таймаута; запрос должен закончиться по таймауту, а приложение продолжит работать.
- `AlwaysFail` — каждый запрос получает `503`. Повторяйте `refresh`, пока circuit breaker не начнёт быстро отклонять запросы.
- `None` — выключает симуляцию. После проверок обязательно верните этот режим:

  ```powershell
  Invoke-RestMethod -Method Post -Uri http://localhost:5168/api/debug/failure-mode/None
  ```

Во время фоновой синхронизации ручной запрос может получить `409`, потому что одновременно разрешена только одна синхронизация.

## Проверка карты GeoJSON

Откройте `http://localhost:5168/map.html`. Для линии нужно хотя бы два сохранённых измерения; подождите не меньше одного интервала после успешного первого запроса. Страница загружает траекторию из `GET /api/iss/track.geojson?limit=100`. Leaflet и карта OpenStreetMap загружаются из интернета.

Сам GeoJSON можно посмотреть в Swagger по адресу `GET /api/iss/track.geojson?limit=100`. Координаты в GeoJSON идут в порядке `[долгота, широта]`.

## Запуск Prometheus и Grafana

1. Убедитесь, что приложение запущено на компьютере и `http://localhost:5168/metrics` открывается.
2. В папке `praactic_7-8` создайте локальный файл `.env`. Впишите выбранные вами настройки, например:

   ```text
   GRAFANA_ADMIN_USER=admin
   GRAFANA_ADMIN_PASSWORD=придумайте_свой_локальный_пароль
   PROMETHEUS_PORT=9090
   GRAFANA_PORT=3000
   ```

   Не отправляйте `.env` в Git. Он уже добавлен в `.gitignore`.

3. В той же папке запустите:

   ```powershell
   docker compose up -d
   ```

4. Prometheus будет доступен на `http://localhost:9090`, Grafana — на `http://localhost:3000`. Войдите в Grafana с логином и паролем из `.env`. Источник Prometheus и dashboard создаются автоматически.
5. Если порт API отличается от `5168`, измените адрес в `prometheus/prometheus.yml` на `host.docker.internal:ВАШ_ПОРТ`.
6. Откройте папку dashboard **ISS Tracker** в Grafana. Там есть панели частоты синхронизаций, частоты ошибок и средней длительности.
7. Чтобы остановить контейнеры, выполните:

   ```powershell
   docker compose down
   ```

## Где смотреть логи

Основные сообщения видны в окне Visual Studio или PowerShell. Дополнительно приложение создаёт ежедневные файлы в `IssTracker.Api/logs`. Хранятся последние семь файлов.

Проект использует HTTP только для локального учебного запуска. При публикации приложения следует включить HTTPS.
