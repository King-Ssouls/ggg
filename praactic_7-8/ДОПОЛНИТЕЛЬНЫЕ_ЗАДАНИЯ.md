# Дополнительные задания и файлы

В проект добавлены оба задания из практической работы: GeoJSON-траектория с картой и мониторинг через Prometheus/Grafana.

## Дополнительное задание 1 — траектория на карте

| Файл или адрес | Для чего нужен |
| --- | --- |
| `IssTracker.Api/Controllers/IssController.cs` | Метод `GET /api/iss/track.geojson` выбирает последние точки и отдаёт Feature с геометрией LineString. |
| `IssTracker.Api/wwwroot/map.html` | Веб-страница с картой, линией траектории, маркером последней точки и временем измерения. |
| `GET /api/iss/track.geojson?limit=100` | API-адрес, из которого карта получает сохранённые координаты. |

Порядок координат в GeoJSON — `[longitude, latitude]`, как требует формат. Сначала берутся последние точки, затем они сортируются от старой к новой. Параметр `limit` ограничен диапазоном 2–500. Для построения линии в базе должны быть минимум две записи.

Страница карты использует Leaflet и подложку OpenStreetMap. Она получает координаты только от нашего API; сам API обращается к Where the ISS at.

## Дополнительное задание 2 — Prometheus и Grafana

| Файл | Для чего нужен |
| --- | --- |
| `IssTracker.Api/Metrics/IssMetrics.cs` | Создаёт счётчик попыток, счётчик ошибок и гистограмму времени синхронизации. |
| `IssTracker.Api/Program.cs` | Подключает HTTP-метрики и открывает `/metrics`. |
| `prometheus/prometheus.yml` | Настраивает адрес приложения и интервал сбора метрик. |
| `docker-compose.yml` | Запускает контейнеры Prometheus и Grafana и задаёт их образы и порты. |
| `grafana/provisioning/datasources/prometheus.yml` | Автоматически подключает Grafana к Prometheus. |
| `grafana/provisioning/dashboards/provider.yml` | Настраивает автоматическую загрузку dashboard. |
| `grafana/provisioning/dashboards/iss-dashboard.json` | Готовая панель с частотой синхронизаций, ошибками и средней длительностью. |
| `.gitignore` | Не даёт случайно добавить локальный `.env`, логи и базу данных в Git. |

### Метрики на панели

- `rate(iss_sync_attempts_total[5m])` — попытки синхронизации в секунду.
- `iss_sync_failures_total` — общее число окончательных ошибок.
- Значения `_sum` и `_count` у `iss_sync_duration_seconds` — средняя длительность синхронизации.

В метрики не добавлены координаты, время измерения и id записи как labels: таких значений слишком много, и они быстро создают большое число отдельных рядов.

## Какие файлы показать преподавателю

1. В `IssController.cs` покажите выдачу GeoJSON, а в `wwwroot/map.html` — карту.
2. В `IssMetrics.cs` покажите три пользовательские метрики.
3. В `prometheus.yml` покажите scrape interval и адрес API.
4. В `docker-compose.yml` покажите два контейнера.
5. В `iss-dashboard.json` покажите определения трёх панелей Grafana.
6. Запустите приложение, затем контейнеры. Включите `FailTwice` или `AlwaysFail` и покажите изменение метрик на dashboard.

Чтобы использовать Grafana, нужно создать локальный `.env` с собственным паролем. Такой файл намеренно не входит в проект и игнорируется Git.
